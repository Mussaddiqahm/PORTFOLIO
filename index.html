Research paper

Multi-Cloud Data Leakage: Risk Surfaces Across Providers

An examination of how data exposure risk grows when organizations split storage and workloads across AWS, Azure, and GCP for reliability — and where that reliability gain trades off against a wider attack surface.

Abstract

Writing

Data — collected or generated facts and figures — underpins decision-making and prediction, and its storage has shifted from physical media to remote cloud infrastructure accessible over the internet. Cloud storage adds layered encryption, firewalling, and authentication that generally make it more secure than local physical storage, with AWS, Azure, and GCP each carrying their own strengths — enterprise and developer tooling, Microsoft-ecosystem integration, and AI/big-data workloads respectively. Multi-cloud strategies, which split data and workloads across two or more of these platforms, improve reliability: if one provider goes down, workloads shift automatically to keep critical applications running with minimal downtime. That same distribution, however, is what makes data leakage one of the most pressing security concerns in multi-cloud systems — every hop between platforms is a fresh opportunity for exposure.

Identified leakage vectors
  • Misconfiguration — storage buckets, permissions, or network rules left open across provider boundaries.
  • Over-permissioning — excess user access and shared credentials across teams instead of scoped, individual access.
  • Exposed or outdated APIs — unauthorized or legacy API versions left reachable between cloud environments.
  • Man-in-the-Middle exposure — sensitive data becoming visible in transit during cloud-to-cloud movement if the network path is monitored.
